# Arena agent mode 额度用法

2026-09-24。只根据 Arena 帮助中心两篇文章的可见说明，加上本会话已经碰到的压缩行为。没有单价表，不把别的产品的 Arena 文档当成这里的计费规则。

帮助中心可见的事实：

- 每日额度从当天第一条提示开始计算，24 小时后刷新。接近上限时输入栏会有指示。用尽后要等刷新，不是本会话能加额度。
- Text Arena 或 Code Arena 的 Battle Mode 不计入这份每日额度。那不是 Agent Mode 的省法，不能把工作改去 Battle 来绕过这里的任务。
- 普通聊天碰到会话 token 上限后，帮助中心写明只能新开对话，而且不能把上下文转到新对话。
- Agent Mode 会把变长的旧对话压成摘要再继续，所以比普通聊天更不容易撞上那条会话上限。压缩会丢掉细节。没写入仓库的入口、标识和未保存判断，不能靠下一轮记忆找回。

本模式里实际省额度的做法：

1. 一句只交一个里程碑。不要在同一句里并行证书、外发、取名和目录核对。
2. 已读过的文件不整份重读。只打开本句点名的那一页或那一块。
3. 云端文件夹先列文件名。正文只读本句要核对的文件，不把整夹下载进仓库。
4. 标识若还要用，写进当轮能留下的笔记，但公开答复和新 Git 仍不写 Drive 链接或标识。没留下的入口不要用搜索去猜。
5. 回复写结论和停点。长表放仓库文件，不在聊天里再贴一遍全文。
6. 不重跑已经失败的通道，不重答已经结案的容量问题。
7. 不生成图片、语音或长服务器，除非这一句就是要那个产物。

省额度不是少做核对。已读文件不整份重读。未读正文不能说成已学。
